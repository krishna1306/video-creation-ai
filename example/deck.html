Stage 05  /  Video

Render on a virtual clock, not a screen recorder.

Screen recording

Real time, best effort

Under load the capture falls one to fourteen seconds behind the page. Animations look almost synced.

Virtual clock

Paused, seeked, captured

Timers, requestAnimationFrame and CSS animations are paused, then seeked to each frame's exact time in headless Chromium.

A step fired at frame n is on screen at frame n.

VO: "Stage five renders the video. A [>] screen recorder runs in real time, and under load it can fall seconds behind. Instead, the renderer uses a [>] virtual clock: timers and CSS animations are paused, then seeked to the exact time of every frame. So [>] a step fired at frame N is on screen at frame N, no matter how slowly the frames are captured."
